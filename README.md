# Discord Backup Bot

Бот сохраняет сервер в SQLite и локальные файлы, затем создаёт его структуру и перепубликует сохранённые сообщения на другом сервере. Команды доступны только владельцам серверов; восстановить снимок может тот же пользователь, который его создал.

Репозиторий содержит исходный код и тесты. Для готовой версии Windows x64 используйте архив из раздела Releases, если владелец репозитория его опубликовал, или соберите архив самостоятельно по инструкции ниже. Инструкция для получателя готовой программы: [README-WINDOWS.md](README-WINDOWS.md). Личные токены и резервные копии в проект не входят.

Для macOS доступны отдельные сборки для Apple Silicon и Intel; инструкция для готового приложения находится в [README-MACOS.md](README-MACOS.md). Собрать архив можно на соответствующем Mac с Python 3.12: `python3 -m pip install -r requirements-build.txt`, затем `python3 build_macos.py`. GitHub Actions также собирает и проверяет оба варианта на macOS 15.

Лицензия проекта — [MIT](LICENSE).

## Сборка готового приложения для Windows

На Windows x64 с установленным Python x64 выполните в папке проекта:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-build.txt
.\.venv\Scripts\python.exe build_windows.py
```

Готовый архив появится в `dist/Discord-Backup-Bot-Windows-x64.zip`. Он содержит исполняемый файл, инструкцию, команды запуска и **только шаблон** `.env`, а не ваши настройки или папку `data`. Получатель распаковывает архив и указывает собственный токен. Проверьте содержимое перед публикацией; автоматически загружать архив в GitHub сборщик не будет. Исполняемый файл не имеет цифровой подписи. Тесты проекта автоматически запускаются GitHub Actions после публикации репозитория; проверка на живом сервере Discord выполняется отдельно.

## Быстрый маршрут

1. **Первый раз:** установите Python, создайте приложение и бота в Discord Developer Portal, включите Message Content Intent, пригласите бота на оба сервера и настройте `.env` по разделу [«Установка на Windows»](#установка-на-windows).
2. **Каждый запуск:** откройте PowerShell в папке проекта и выполните `.\.venv\Scripts\python.exe -u bot.py`. Дождитесь сообщения о подключении и оставьте окно открытым.
3. **На исходном сервере:** владелец запускает `/backup`, затем `/backup_info` и записывает номер снимка.
4. **На новом сервере:** тот же пользователь, будучи владельцем нового сервера, запускает `/restore`, указывает номер в поле `backup_id` и при желании выбирает `mode`.
5. Дождитесь завершения и вызовите `/restore_info`. Сверьте каналы, роли, сообщения и предупреждения. Для нового запуска бота снова выполните команду из пункта 2; для остановки после завершения операций нажмите `Ctrl+C`.

Если бот уже настроен в этой папке, заново создавать приложение и заменять `.env` не нужно: переходите к пункту 2. Команды `/backup` и `/restore` вводятся **в Discord**, а команда запуска Python — **в PowerShell**.

## Перед началом

Понадобятся компьютер с Windows, интернет, Python 3.10 или новее, место на диске для базы и вложений, а также два сервера Discord. Для первого запуска удобно использовать Python 3.12. Снимок создаёт владелец исходного сервера, а восстановление запускает **тот же аккаунт Discord**, который также должен владеть целевым сервером. Боту нужны доступ к содержимому и истории каналов, а на целевом сервере — права создавать роли, каналы и сообщения.

Проверьте работу сначала на двух небольших тестовых серверах. Сообщения на целевом сервере публикуются от имени бота с указанием первоначального автора и времени; это не полное клонирование сервера.

## Установка на Windows

### 1. Распакуйте проект и установите Python

Распакуйте ZIP в отдельную постоянную папку. Установите [Python для Windows](https://www.python.org/downloads/windows/), если его ещё нет. В PowerShell проверьте установку:

```powershell
py -3 --version
```

Откройте PowerShell **в папке проекта**: например, откройте папку в проводнике, введите `powershell` в адресной строке и нажмите Enter. В ней должны находиться `bot.py`, `requirements.txt` и `.env.example`.

### 2. Создайте приложение Discord

1. Откройте [Discord Developer Portal](https://discord.com/developers/applications), войдите в Discord и нажмите **New Application**.
2. Откройте созданное приложение и раздел **Bot**. При необходимости создайте или сбросьте токен бота и сохраните его для следующего шага. Токен — секрет: не вставляйте его в чат, снимки экрана или архив для других людей.
3. В разделе **Bot → Privileged Gateway Intents** включите **Message Content Intent** и сохраните изменения. Без него содержимое сообщений, вложения и embeds могут быть недоступны; некоторым приложениям требуется одобрение Discord. Подробнее — в [документации Discord](https://support-dev.discord.com/hc/en-us/articles/6207308062871-What-are-Privileged-Intents).
4. В разделе установки приложения настройте **Guild Install** со scopes `bot` и `applications.commands` и правами **Administrator**, затем используйте ссылку установки, чтобы пригласить бота на оба сервера. Интерфейс портала может меняться; добавление бота требует соответствующих прав на сервере.
5. В настройках каждого сервера поднимите роль бота достаточно высоко, чтобы он мог управлять нужными ролями и каналами. Роли выше роли бота ему недоступны даже при наличии Administrator. Для форумов и новостных каналов на целевом сервере должны поддерживаться соответствующие возможности Community.

### 3. Установите зависимости и настройте токен

В открытом в папке проекта PowerShell выполните следующие команды. Если `.env` уже существует, пропустите команду `Copy-Item`, чтобы не перезаписать свои настройки.

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
notepad .env
```

В открывшемся файле замените `вставьте_токен_бота` токеном из Developer Portal, сохранив строку вида `DISCORD_TOKEN=...`. Сохраните файл и закройте Блокнот. Если файл `.env` уже существует, не перезаписывайте его шаблоном: откройте существующий файл напрямую.

### 4. Запустите бота

```powershell
.\.venv\Scripts\python.exe -u bot.py
```

После подключения в консоли появится сообщение о запуске. Держите окно открытым на время работы: при закрытии окна или выключении компьютера бот остановится. Для остановки после завершения всех операций нажмите `Ctrl+C`. Чтобы запустить его снова, откройте PowerShell в папке проекта и повторите команду выше. Одновременно запускайте только один экземпляр бота с этой базой.

Бот регистрирует глобальные slash-команды при подключении; Discord может показать их не сразу. Введите `/` на сервере и выберите команду своего бота. Ответы на команды видны только вызывающему пользователю.

## Команды

Все команды вызываются на сервере и доступны только его владельцу. `backup_id` — номер **снимка**, а не ID сервера; его можно узнать через `/backup_info`.

| Команда | Действие |
| --- | --- |
| `/backup` | Создать снимок текущего сервера. |
| `/backup_info` | Показать последние снимки этого пользователя. |
| `/backup_info backup_id:1` | Показать сведения и замечания для снимка № 1. |
| `/restore backup_id:1` | Восстановить снимок № 1 на текущем сервере; `mode` можно выбрать дополнительно. |
| `/restore_info` | Показать историю восстановлений на текущем сервере. |
| `/wipe_test` | Сразу очистить подходящий тестовый сервер перед повторным восстановлением. |
| `/wipe_info` | Показать последнюю очистку текущего сервера. |

`/wipe_test` удаляет каналы, сообщения в них и обычные роли; текущий текстовый канал сохраняется. Подробности и ограничения описаны ниже.

### Как вводить команды в Discord

Откройте обычный текстовый канал нужного сервера, в поле сообщения введите `/` и начните печатать имя команды. Выберите команду этого бота из списка Discord, заполните появившиеся поля и нажмите Enter. Записи вида `/restore backup_id:1` ниже показывают имя команды и значение поля: интерфейс Discord может предлагать их как отдельные интерактивные поля. Ответ бота виден только вызвавшему команду пользователю.

### Создать копию: `/backup`

1. Откройте **исходный** сервер, который принадлежит вашему аккаунту, и убедитесь, что бот добавлен на него и запущен на компьютере.
2. Введите `/backup`, выберите команду бота и отправьте её. Параметры не нужны.
3. Дождитесь ответа; для большой истории и множества файлов это может занять продолжительное время. Не выключайте компьютер и не закрывайте бот, пока операция выполняется.
4. Запишите номер после `#` и статус. Например, `Снимок #3: complete` означает, что номер для восстановления — `3`. Это пример; используйте номер из своего ответа.

### Найти копию и предупреждения: `/backup_info`

- `/backup_info` без параметров показывает до 20 последних снимков, созданных вашим аккаунтом.
- Чтобы изучить конкретный снимок, выберите `/backup_info`, укажите его номер в поле `backup_id`, например `3`, и отправьте команду. Строка `/backup_info backup_id:3` в инструкции означает именно эти действия.
- `complete` — обнаруженных ошибок чтения нет; `partial` — есть ошибки, проверьте предупреждения; `failed` — создание завершилось ошибкой; `running` — операция идёт либо была прервана. Статус `complete` не обещает копирование функций Discord, перечисленных в разделе ограничений. Ответ Discord может обрезать длинный список предупреждений.

### Восстановить копию: `/restore`

1. Создайте отдельный целевой сервер под тем же аккаунтом, который создавал копию. Пригласите бота и дайте ему необходимые права; убедитесь, что его роль выше ролей, которыми он должен управлять.
2. На **целевом**, а не исходном сервере выберите `/restore`. В обязательное поле `backup_id` введите номер снимка, например `3`.
3. Необязательное поле `mode` оставьте пустым для отдельных сообщений либо выберите **«Компактно»**, чтобы объединять соседние короткие сообщения. Затем отправьте команду.
4. Дождитесь завершения. Если ответ долго не приходит или исчез, вызовите `/restore_info` на целевом сервере: там хранится журнал восстановления. Проверьте предупреждения и созданные данные.

Бот создаёт новые каналы и роли, не очищая существующие, и меняет права `@everyone`. Восстановление на исходный сервер запрещено. Повтор одного снимка на тот же сервер заблокирован до успешной очистки; восстановление другого снимка может создать дубликаты. Автоматического отката нет.

### Проверить восстановление: `/restore_info`

На целевом сервере выберите `/restore_info` без параметров. Команда показывает до 10 записей для текущего сервера и вашего аккаунта, включая номер восстановления, номер снимка, статус и детали. Если после остановки бота остался `running`, операция могла примениться частично: сначала проверьте сервер, не удаляйте базу и не редактируйте статусы вручную.

### Очистить тестовый сервер: `/wipe_test` и `/wipe_info`

`/wipe_test` предназначена только для целевого тестового сервера, где этот бот уже запускал восстановление. **Она начинает необратимую очистку сразу после вызова:** удаляет другие каналы с сообщениями и обычные роли. Текущий текстовый канал остаётся вместе со своими сообщениями; роль `@everyone` и управляемые интеграциями роли тоже остаются. Перед вызовом убедитесь, что находитесь именно на тестовом сервере и открыли канал, который хотите оставить.

Выберите `/wipe_test` без параметров и дождитесь ответа, затем вызовите `/wipe_info`, чтобы проверить последнюю очистку. Если статус `complete`, можно повторить восстановление; если очистка неполная или прервана, повтор остаётся заблокированным. На сервере, для которого в этой базе есть снимок, команда запрещена.

## Использование

1. На исходном сервере его владелец выполняет `/backup`. Дождитесь окончания и запомните ID снимка.
2. `/backup_info` показывает последние снимки пользователя; `/backup_info backup_id:1` показывает сведения и предупреждения для снимка № 1.
3. Создайте новый сервер под **тем же аккаунтом**, пригласите туда бота и выполните на нём `/restore backup_id:1`.

При восстановлении можно выбрать параметр `mode`: **«Отдельные сообщения»** (по умолчанию) или **«Компактно»**. Компактный режим объединяет соседние короткие текстовые сообщения в блоки до 1900 единиц UTF-16, сохраняя их порядок и подписи с автором и временем. Поэтому несколько исходных сообщений становятся одним сообщением Discord. Перед сообщениями с вложениями или embeds блок закрывается. Если у сообщения есть вложения, но нет embeds, текст и доступные файлы объединяются в один или несколько запросов, учитывающих размер и число файлов. При отклонении пакета как некорректного или слишком большого файлы отправляются отдельно. Длинные тексты разбиваются по границам символов; оформление Markdown на границе сообщений может отображаться иначе.

Бот создаёт новые объекты и меняет права `@everyone` на целевом сервере. Существующие каналы и роли не удаляются. На исходном сервере восстановление заблокировано. Повтор для той же пары «снимок и целевой сервер» запрещён до успешной очистки командой `/wipe_test`, чтобы избежать дубликатов. Восстановления разных снимков на один сервер могут создать дубликаты. Автоматического отката и продолжения с места остановки нет.

Discord может выдать нескольким ролям одинаковую числовую позицию, даже если роль бота отображается выше остальных. Если нужные позиции невозможно выставить, бот продолжает восстановление и сообщает, что порядок ролей нужно проверить вручную. Сами разрешения ролей при этом сохраняются отдельно.

Статус снимка отображается в `/backup_info`: `complete` означает завершение без обнаруженных ошибок чтения, `partial` — были ошибки доступа или скачивания, `failed` — операция завершилась ошибкой, `running` — операция выполняется или была прервана остановкой процесса. Для `partial` изучите замечания перед восстановлением: часть данных может отсутствовать. Статус `complete` не означает поддержки всех возможностей Discord, перечисленных ниже. Снимки, созданные до введения статуса `partial`, следует проверить вручную: прежде они могли получить статус `complete` даже при ошибках.

`/restore_info` показывает журнал восстановлений на текущем сервере. Статус `running` после остановки бота означает, что операция могла прерваться; изменения на сервере могли примениться частично. Информация остаётся в базе, даже если действие занимает больше времени, чем срок жизни ответа slash-команды. Во время операции не запускайте второй экземпляр бота с той же базой.

## Очистка тестового сервера

Команда `/wipe_test` доступна только владельцу сервера, на котором уже запускалось восстановление. Она необратимо удаляет все каналы вместе с сообщениями и обычные роли, кроме текущего текстового канала, который остаётся для управления вместе с его сообщениями. Роль `@everyone` и управляемые интеграциями роли остаются. Команда запрещена на сервере, для которого в этой базе есть снимок, и во время незавершённого восстановления.

В обычном текстовом канале, который хотите сохранить, вызовите `/wipe_test` без параметров. Команда сразу очистит текущий сервер. После успешной проверки очистки можно снова запускать `/restore`. Статус очистки можно посмотреть через `/wipe_info`. Если какие-то объекты удалить не удалось, очистка считается неполной и повторное восстановление остаётся заблокированным. Данные и журнал в локальной папке `data` очистка не удаляет.

## Что сохраняется и ограничения

- Роли, их обычные права и параметры, категории, текстовые, новостные, голосовые, stage, forum и media каналы, основные настройки и индивидуальные права каналов. Порядок зависит от ограничений и иерархии ролей Discord.
- История текстовых, новостных, голосовых и stage каналов, доступные активные и архивные ветки, публикации форумов и их теги. Сохраняются автор, дата, текст, embeds и доступные файлы. Файлы лежат в `data/attachments`, метаданные и текст — в `data/backups.sqlite3`. Сделайте копию **всей папки data** и защитите её: в ней могут быть личные сообщения и файлы участников.
- Сообщения публикуются ботом заново с указанием исходного автора и даты, без уведомлений от упоминаний. Исходные ID и даты создания Discord сохранить нельзя. Вложения и embeds могут отправляться отдельными сообщениями; файлы выше лимита нового сервера и embeds, отклонённые Discord, пропускаются с предупреждением. Ссылки на старые файлы внутри embeds могут перестать работать.
- Приватные ветки создаются приватными, но состав их участников не переносится. Для форумной публикации бот сначала создаёт служебное сообщение, затем отправляет сохранённую историю. Новые снимки сохраняют отображаемый текст системных событий и название со ссылкой для стикеров; файл стикера не архивируется. В снимках, созданных до добавления этой поддержки, сведения могли отсутствовать. Ссылки между сообщениями, закрепления, реакции, стикеры как объекты Discord, эмодзи, вебхуки, приглашения, назначение ролей участникам и некоторые настройки сервера не переносятся. Интеграционные роли не создаются. Если роль или участник из индивидуальных прав отсутствует на новом сервере, бот создаёт канал и переносит доступные права, пропуская только неразрешённые записи. В `/restore_info` появится предупреждение: **доступ к такому каналу может отличаться от исходного**, проверьте его вручную. Для копий с приватной историей используйте закрытый архивный сервер.
- Снимки, сделанные до добавления поддержки веток и форумов, их не содержат — создайте новый снимок. Снимок делается последовательно, а не атомарно: изменения сервера во время копирования могут попасть в него не полностью. Для точного переноса ограничьте изменения на исходном сервере на время копирования.
- Доступные сведения зависят от прав бота и настроек Discord. Ошибки чтения каналов и загрузки вложений отмечаются в `/backup_info`; такой снимок может быть неполным. Предупреждения могут обрезаться в ответе Discord — полный список содержится в таблице `backups` базы. Проверяйте ограничения и результат перед использованием.

Сохраняйте данные только тех серверов, для резервного копирования которых у вас есть полномочия. Не передавайте архив посторонним.

## Локальные проверки

Перед переносом копии или после копирования папки `data/` остановите бота и проверьте снимки:

```powershell
.\.venv\Scripts\python.exe verify_backup.py
.\.venv\Scripts\python.exe verify_backup.py --backup-id 1
.\.venv\Scripts\python.exe verify_backup.py --data-dir "D:\BotData"
```

Проверка открывает базу только для чтения, проверяет целостность SQLite, статусы снимков, основные данные сообщений и наличие перечисленных файлов вложений. Код завершения: `0` — обнаруженных проблем нет, `1` — найдены проблемы или снимок имеет статус, отличный от `complete`, `2` — проверку не удалось выполнить. Она не проверяет все поля и возможности Discord, не подтверждает полноту исходного сервера и не сравнивает содержимое вложений по контрольным суммам: в существующих снимках суммы не записаны. Для уверенности проверьте восстановление на тестовом сервере. Если указан `--backup-id`, целостность SQLite проверяется для всей базы, а данные и файлы — для выбранного снимка.

Снимки и базу не изменяйте во время проверки. Для переноса резервной копии остановите бота и скопируйте папку `data` целиком, а не только SQLite-файл: вложения находятся отдельно. Восстановление использует те же локальные файлы и отклоняет пути вложений за пределами папки соответствующего снимка.

Запуск тестов:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Тесты используют имитации объектов Discord и не заменяют проверку на двух настоящих тестовых серверах.

## Передача другому человеку

Для передачи **самой программы** отправьте ZIP, содержащий `README.md`, `.env.example`, `requirements.txt`, файлы `bot.py`, `attachments.py`, `storage.py`, `transfer.py`, `verify_backup.py` и при желании папки `tests` и `benchmarks`. Получатель распакует архив, создаст собственное приложение Discord, настроит свой `.env` и установит зависимости по инструкции выше. Передавать своё приложение или токен для этого не нужно.

Не включайте в обычный архив:

- `.env` — в нём находится секретный токен;
- `data/` — в нём хранятся снимки, сообщения, вложения и журналы;
- `.venv/`, `.deps/`, `__pycache__/` и `*.pyc` — это локальное окружение и кэш, получатель создаст своё окружение;
- журналы и прочие личные файлы. Проверьте состав ZIP перед отправкой.

Если нужно перенести **свои снимки** на другой компьютер, это отдельная операция: дождитесь завершения работы, остановите бота и скопируйте всю папку `data/`, включая базу и вложения, защищённым способом. На новом компьютере установите программу и разместите папку `data/` рядом с `bot.py`. Для восстановления снимка по-прежнему нужен тот же аккаунт Discord, который его создавал, и он должен владеть целевым сервером. Само приложение бота можно настроить заново. Не запускайте два процесса бота одновременно с одной базой. Снимки могут содержать личные данные участников; передавайте их только тем, кому доверяете.

## Частые вопросы

**`py` не найден или виртуальное окружение не создаётся.** Установите Python, закройте и снова откройте PowerShell, затем проверьте `py -3 --version`. Если команда `python --version` работает, вместо первой команды создания окружения можно использовать `python -m venv .venv`.

**Не устанавливаются зависимости.** Убедитесь, что PowerShell открыт в папке с `requirements.txt`, есть подключение к интернету и команда запускает Python из `.venv`. Повторите `.\.venv\Scripts\python.exe -m pip install -r requirements.txt` и посмотрите текст ошибки.

**Бот не подключается или пишет об ошибке токена.** Проверьте, что `.env` лежит рядом с `bot.py`, содержит строку `DISCORD_TOKEN=...` с токеном бота без лишних символов, а токен не был сброшен в Developer Portal. Не отправляйте токен вместе с сообщением об ошибке.

**Команды не видны.** Убедитесь, что процесс бота запущен и подключился, приложение установлено на сервер с доступом к командам, а вы вводите `/` именно на сервере. Глобальная регистрация может занять некоторое время; при необходимости перезапустите клиент Discord.

**«Команда доступна только владельцу сервера».** Команду должен вызвать владелец текущего сервера; прав администратора у другого участника недостаточно.

**Снимок не найден.** Проверьте номер через `/backup_info`, используйте тот же аккаунт Discord, который создавал снимок, и убедитесь, что бот работает с той же папкой `data`. Восстановить можно снимки со статусом `complete` или `partial`.

**Нет части сообщений или объектов.** Проверьте `/backup_info backup_id:1` для своего номера, права бота на исходном сервере и Message Content Intent. При восстановлении изучите `/restore_info`, права и иерархию ролей на целевом сервере, а также ограничения в разделе выше.

**Операция прервана или повтор заблокирован.** Посмотрите `/backup_info`, `/restore_info` или `/wipe_info` и консоль. `running` после остановки может означать прерванную операцию, а изменения на сервере — частично примениться. Автоматического безопасного продолжения нет: не удаляйте базу и не правьте статусы вручную, пока не разобрались с состоянием сервера и копией данных.

## Устройство и скорость

Код команд и операций находится в `bot.py`, чтение сообщений из SQLite — в `storage.py`, ограниченный запуск параллельных задач — в `transfer.py`. Восстановление создаёт структуру сервера и затем отправляет историю максимум четырёх каналов одновременно; внутри каждого канала сообщения идут по порядку. При ошибке переноса остальные задачи отменяются, а операция помечается как неуспешная.

База читается страницами по 100 записей, поэтому курсор не остаётся открытым во время ожидания Discord. При создании копии сообщения буферизуются до 100 записей или приблизительного верхнего предела 1 МиБ и записываются короткой транзакцией; полученные сообщения сохраняются и при ошибке чтения истории. Индекс ускоряет поиск сообщений конкретного канала. Реальное время восстановления зависит от числа сообщений, вложений и ограничений Discord; библиотека обрабатывает ответы о лимитах запросов. Ускорение не измерялось на реальном восстановлении.

Локальный синтетический тест записи SQLite можно запустить командой `.\.venv\Scripts\python.exe benchmarks\sqlite_write.py`. Он не использует резервные копии и не измеряет сетевую скорость Discord.
