# Discord Backup Bot — готовая версия для Windows

Программа сохраняет структуру сервера Discord и доступную историю в локальную папку `data`, а затем может восстановить их на другом сервере. Windows x64, Python устанавливать не нужно. Компьютер должен быть подключён к интернету и оставаться включённым во время операции.

## Состав

- `DiscordBackupBot.exe` — программа бота и проверки снимков.
- `1 - Edit Token.cmd` — открыть настройки токена.
- `2 - Start Bot.cmd` — запустить бота в консоли.
- `3 - Check Backups.cmd` — проверить локальные снимки.
- `.env` — настройки с вашим токеном; не отправляйте этот файл другим людям после настройки.
- `LICENSE` — условия лицензии MIT.
- `data` — появится при первом запуске; содержит резервные копии, сообщения и файлы.

Сначала распакуйте **весь архив** в отдельную постоянную папку с правом записи, например `Документы\Discord Backup Bot`. Не запускайте файлы прямо из окна ZIP. Рядом с программой должно хватать места для резервных копий и вложений.

## 1. Создайте бота и получите токен

1. Войдите в [Discord Developer Portal](https://discord.com/developers/applications) и создайте приложение кнопкой **New Application**.
2. Откройте раздел **Bot**. При необходимости создайте или сбросьте токен и сохраните его в безопасном месте. Токен даёт доступ к вашему боту; не отправляйте его людям и не публикуйте.
3. В разделе **Bot → Privileged Gateway Intents** включите **Message Content Intent** и сохраните изменения. Без него данные сообщений и вложений могут быть недоступны. Discord может требовать отдельного одобрения для некоторых приложений.
4. В настройках установки приложения включите **Guild Install**, scopes `bot` и `applications.commands`, разрешение **Administrator** и получите ссылку установки. По ней добавьте бота на исходный и целевой сервер. Для добавления потребуются соответствующие права на сервере.
5. В настройках обоих серверов убедитесь, что бот видит нужные каналы и их историю. На целевом сервере поднимите роль бота выше управляемых ролей, чтобы он мог создавать роли и каналы. Для форумов и новостных каналов могут потребоваться функции Community.

## 2. Укажите токен и запустите

1. Дважды нажмите `1 - Edit Token.cmd`. В Блокноте откроется файл `.env`.
2. Замените `вставьте_токен_бота` на **свой** токен; оставьте одну строку вида `DISCORD_TOKEN=ваш_токен` без кавычек. Сохраните файл и закройте Блокнот. Не размещайте токен в чате или скриншотах.
3. Дважды нажмите `2 - Start Bot.cmd`. Дождитесь сообщения о подключении и оставьте окно открытым. Одновременно запускайте только один экземпляр бота с этой папкой `data`.
4. На время копирования и восстановления не закрывайте окно и не выключайте компьютер. После завершения операций остановите бота сочетанием `Ctrl+C`. Для повторного запуска снова откройте `2 - Start Bot.cmd`.

Если Windows SmartScreen показывает предупреждение для неподписанной программы, проверьте происхождение архива у отправителя перед запуском. Некоторые настройки безопасности организации могут запрещать такие приложения.

## 3. Создайте снимок

Команды вводятся **в Discord**, а не в окно программы. Их может использовать только владелец текущего сервера. В поле сообщения введите `/`, выберите команду этого бота и нажмите Enter.

1. На исходном сервере вызовите `/backup` и дождитесь завершения. Запишите номер после `#`.
2. Вызовите `/backup_info`, чтобы увидеть список последних снимков, либо выберите эту команду и укажите номер в поле `backup_id`, чтобы увидеть сведения и предупреждения.
3. `complete` означает отсутствие обнаруженных ошибок чтения; `partial` — обнаружены проблемы, проверьте предупреждения; `failed` — ошибка; `running` — операция идёт либо была прервана. Даже `complete` не означает, что поддерживаются все функции Discord.

## 4. Восстановите на другом сервере

1. Создайте отдельный сервер под **тем же аккаунтом Discord**, который создал снимок. Этот аккаунт должен владеть и исходным, и целевым сервером. Добавьте туда бота.
2. На целевом сервере выберите `/restore`, в поле `backup_id` укажите номер снимка. При желании выберите `mode`: отдельные сообщения или компактные блоки. Отправьте команду.
3. Дождитесь окончания и проверьте `/restore_info`. Если ответ на команду пропал из-за времени выполнения, результат можно найти в журнале `/restore_info`. Проверьте каналы, роли и сообщения вручную.

Бот создаёт новые роли и каналы, не очищает существующие, меняет разрешения `@everyone` и не работает на исходном сервере как цель восстановления. Повтор того же снимка на том же сервере заблокирован до успешной тестовой очистки. Разные снимки могут создавать дубликаты. Автоматического отката нет.

Если недоступны роли или участники, указанные в правах канала, бот пропускает эти записи прав, но создаёт канал и копирует историю. **Доступ к каналу может отличаться от исходного.** Используйте закрытый архивный сервер для приватных данных и проверяйте предупреждения и доступ вручную.

## Команды

| Команда | Назначение |
| --- | --- |
| `/backup` | Сохранить текущий сервер. |
| `/backup_info` | Показать свои последние снимки; необязательное поле `backup_id` показывает детали конкретного снимка. |
| `/restore` | Восстановить свой снимок на текущем сервере; обязательное поле `backup_id`, необязательное `mode`. |
| `/restore_info` | Показать журнал восстановлений на текущем сервере. |
| `/wipe_test` | Немедленно очистить подходящий тестовый сервер для повторного восстановления. |
| `/wipe_info` | Показать последнюю очистку текущего сервера. |

### Важно о `/wipe_test`

Команда **сразу и необратимо** удаляет каналы с сообщениями и обычные роли на текущем сервере, кроме текущего текстового канала и его сообщений. Роль `@everyone` и управляемые интеграциями роли остаются. Вызов возможен только владельцем сервера, где бот уже запускал восстановление. Сервер, для которого в локальной базе есть снимок, защищён от этой команды. При неполной очистке повторное восстановление остаётся заблокировано. Не запускайте команду на сервере с нужными данными.

## Проверка и перенос резервных копий

Остановите бота и запустите `3 - Check Backups.cmd`. Утилита проверяет SQLite, основные данные сообщений, статусы снимков и наличие файлов вложений. Она не подтверждает полноту сервера, содержимое вложений по контрольной сумме или фактическое восстановление в Discord.

Чтобы перенести свои снимки на другой компьютер, остановите бота и безопасно скопируйте **всю** папку `data` рядом с программой. База без папки вложений — неполная копия. Снимки могут содержать личные данные участников; не публикуйте их. Для восстановления нужен тот же аккаунт владельца Discord, который создал снимок.

## Ограничения

Сообщения публикуются заново от имени бота с подписью исходного автора и даты; исходные ID и даты сообщений не сохраняются. Вложения и embeds могут публиковаться отдельно и зависеть от лимитов Discord. Ссылки на старые вложения в embeds могут перестать работать. Приватные ветки создаются приватными, но их участники не переносятся. Реакции, закрепления, назначения ролей участникам, интеграционные роли, эмодзи, вебхуки, приглашения и некоторые настройки сервера не копируются. У стикеров сохраняются только название и ссылка. Снимок не атомарный: изменения сервера во время копирования могут отразиться не полностью.

## Если что-то не работает

- **Окно сразу сообщает, что токен не указан:** откройте `1 - Edit Token.cmd`, укажите токен и сохраните `.env`. После сброса токена в Developer Portal нужно обновить `.env`.
- **Бот не подключается:** проверьте интернет, токен и разрешение на запуск в Windows; не отправляйте токен вместе с ошибкой.
- **Команды не видны:** бот должен работать, быть приглашён на сервер со scope `applications.commands`; глобальная регистрация может занять время. Перезапустите клиент Discord.
- **Команда отклонена:** её вызывает именно владелец текущего сервера; одних прав администратора недостаточно.
- **Снимок не найден:** проверьте `/backup_info`, номер, аккаунт создателя и папку `data`.
- **Не хватает каналов или сообщений:** проверьте права бота и Message Content Intent на исходном сервере, предупреждения снимка и `/restore_info`, а также ограничения выше.
- **Операция прервана или отображает `running` после остановки:** изменения на сервере могли примениться частично. Не удаляйте `data` и не меняйте статусы вручную; сначала проверьте сервер и сохраните копию данных.
